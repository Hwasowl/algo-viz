# 코테 알고리즘 시각화 웹 — 설계 문서

작성일: 2026-06-22
원본: 노션 "38군데 합격 비법, 2026 코테 필수 알고리즘" (딩코딩코)

## 1. 목적

노션 코딩테스트 강의자료의 알고리즘/자료구조 개념을 **Java 개발자 관점으로 재서술**하고,
**좌측 Java 코드 / 우측 인터랙티브 애니메이션**으로 동기화해 보여주어 쉽게 익히는 정적 웹.

## 2. 성공 기준

- 토픽을 선택하면 좌측에 표준 Java 코드, 우측에 그 코드의 실행 상태가 동기화되어 표시된다.
- 재생/일시정지/한 스텝씩/속도 조절이 동작하고, 현재 실행 줄과 시각 상태가 항상 일치한다.
- `npm run build`로 의존성 없는 정적 `dist/`가 생성되어 브라우저에서 바로 열린다.
- Phase 1 4토픽(정렬·이진탐색·BFS/DFS·재귀)이 위 기준을 충족한다.

## 3. 기술 스택

- **Vite + Vue3 (SFC, Composition API)** — 최종 산출물은 정적 `dist/` 번들.
- 코드 하이라이트: `highlight.js` 또는 Shiki (라인 하이라이트 필요 → highlight.js + 직접 라인 마킹).
- 시각화 렌더: 기본 SVG(트리·그래프·배열), 필요 시 Canvas. 외부 애니메이션 라이브러리 미사용(직접 스텝 렌더).
- 빌드 디렉토리: OneDrive 한글 경로 이슈 회피를 위해 Vite `cacheDir`/출력 점검 필요. (`dist`는 프로젝트 내, node 캐시는 `C:/tmp/algo-viz-build` 고려)

## 4. 핵심 아키텍처 — 스텝 동기화 엔진

모든 토픽이 공유하는 단일 패턴.

### 4.1 데이터 계약 (Step)

```ts
interface Step {
  line: number;        // 좌측 코드에서 하이라이트할 줄 (1-based)
  state: object;       // 우측 시각화가 렌더할 스냅샷 (토픽별 형태)
  note?: string;       // 이 스텝 설명 (한 줄)
}
```

알고리즘 로직은 "실행하면서 각 의미 단위마다 `Step`을 push"하는 **제너레이터 함수**로 작성한다.
→ 시각화는 상태를 *해석*만 하고 계산은 하지 않는다. (계산/표현 분리)

### 4.2 컴포넌트 경계

| 컴포넌트 | 책임 | 의존 |
|---|---|---|
| `AppShell` | 라우팅, 사이드바 네비(주차→토픽) | topic 레지스트리 |
| `TopicView` | 한 토픽의 개념 설명 + 분할 패널 조립 | topic 데이터 |
| `CodePanel` | Java 코드 표시 + 현재 줄 하이라이트 | `currentStep.line` |
| `VizStage` | 우측 시각화 호스트, 토픽별 렌더러 슬롯 | `currentStep.state` |
| `StepController` | ◀ ▶ 재생/일시정지/속도/진행바, `currentIndex` 관리 | `steps[]` |
| `renderers/*` | 토픽별 시각 렌더러 (배열바·트리·그래프·콜스택) | `state` (순수) |

각 렌더러는 `state`만 받아 그리는 **순수 표현 컴포넌트** — 내부를 몰라도 사용 가능, 교체해도 컨트롤러 안 깨짐.

### 4.3 토픽 데이터 모듈

```ts
interface Topic {
  id: string;
  week: number;            // 1~5, 방법론은 0
  title: string;
  concept: string;         // Java 개발자 관점 재서술 (마크다운)
  javaCode: string;        // 표준 Java 예제
  complexity: { time: string; space: string };
  buildSteps?: (input) => Step[];   // 애니메이션 토픽만
  rendererId?: string;     // 어떤 renderer를 쓸지
  realWorld?: string;      // Java 표준 라이브러리 대응
}
```

토픽은 `src/topics/<id>.ts`에 1파일씩. 레지스트리(`src/topics/index.ts`)가 주차별로 묶는다.

## 5. 콘텐츠 범위 (전체)

- **주차 커리큘럼:** 1주차 시간·공간복잡도 / 2주차 배열·링크드리스트·이진탐색·재귀 / 3주차 정렬·스택·큐·해쉬 / 4주차 트리·힙·BFS·DFS·DP / 5주차 기출.
- **방법론(주차 0):** 공략법, 디버깅, 구현력 훈련, 구조화 복습, 실무 자료구조 라이브러리 비교표 — 애니메이션 없는 읽기 콘텐츠.
- 모든 코드/개념은 **Java 표준 관점**으로 재서술.

## 6. 단계적 빌드

- **Phase 1 — 골격 + 대표 4토픽**
  - 셸/네비/StepController/CodePanel/VizStage 골격.
  - 정렬(버블·선택·삽입·병합·퀵), 이진탐색, BFS/DFS, 재귀(콜스택).
  - 렌더러: 배열바, 그래프, 콜스택.
- **Phase 2 — 나머지 자료구조**
  - 배열/링크드리스트, 스택/큐, 해쉬, 트리/힙, DP.
- **Phase 3 — 방법론 페이지 + 라이브러리 비교표 + 1주차 복잡도 그래프**

각 Phase 종료 시 브라우저 동작 확인 후 진행.

## 7. 콘텐츠 파이프라인 (노션 → Java)

- 노션 하위 페이지는 외부 공개 사이트(`*.notion.site/{id}`)로만 fetch 가능. 큰 페이지는 임시 파일 청크 읽기.
- 추출한 원문을 그대로 옮기지 않고 **저자가 Java 관점으로 재서술** — 타 언어/의사코드 예제는 표준 Java로 다시 작성.
- 저작권 표기(딩코딩코) 보존, 원문 통문장 복제 지양(재서술).

## 8. 비범위 (YAGNI)

- 런타임 Notion 연동, 로그인, 백엔드 없음 (정적 번들).
- 사용자 코드 편집/실행기 없음 (미리 정의된 스텝 재생만).
- 모바일 최적화는 후순위(데스크톱 우선, 깨지지 않을 정도만).

## 9. 위험 요소

- 콘텐츠 재서술이 사실상 저작 작업이라 분량이 큼 → Phase로 분할해 흡수.
- OneDrive 한글 경로에서 Vite/node 도구 경로 깨짐 가능 → 빌드 캐시를 `C:/tmp`로 우회.
- 스텝 제너레이터-렌더러 계약이 토픽마다 state 형태가 달라짐 → rendererId로 명시 매핑.
